# New-Programming-Languages-2026

Индивидуальная работа: 20 программ на 20 разных языках программирования.
Пять тем, на каждую тему — по 4 программы. Специализированные библиотеки не используются — только стандартная библиотека каждого языка (потоки/tasks, сокеты, файловый ввод-вывод).

## Структура репозитория

Каждая задача выполняется в отдельной ветке вида `<номер темы>_task_<номер задачи>_<язык>` (например, `1_task_1_rust`). 
Готовые исходники лежат в папках соответствующих тем:

```text

│   ├── task_1_haskell/

## Тема 1. Многопоточность

Папка: `1_threads/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Параллельный расчет GC-состава | Rust | `1_task_1_rust` |
| 2 | Параллельное моделирование мутаций ДНК | Elixir | `1_task_2_elixir` |
| 3 | Перевод RGB в оттенки серого | Nim | `1_task_3_nim` |
| 4 | Параллельный поиск генетического мотива | Mojo | `1_task_4_mojo` |

1.1 **Rust.** Программа вычисляет процент нуклеотидов G и C. Строка разбивается на фрагменты, каждый поток обрабатывает свою часть, после чего результаты суммируются.

1.2 **Elixir.** Несколько процессов параллельно обрабатывают набор ДНК-последовательностей, внося случайные мутации с заданной вероятностью. Подсчитывается количество замен по позициям, после чего результаты от всех процессов объединяются в общую статистику.

1.3 **Nim.** Перевод массива пикселей в значения яркости по стандартной формуле `0.3*R + 0.59*G + 0.11*B`. Потоки делят массив между собой для параллельной обработки.

1.4 **Mojo.** Поиск заданного короткого паттерна в последовательности ДНК. Строка делится на блоки, потоки параллельно ищут совпадения.

## Тема 2. Алгоритмические задачи

Папка: `2_algorithms/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Расстояние Левенштейна (рекурсия) | Haskell | `2_task_1_haskell` |
| 2 | Моделирование популяции по Харди-Вайнбергу (рекурсия) | Scheme | `2_task_2_scheme` |
| 3 | Поиск частого k-мера | Zig | `2_task_3_zig` |
| 4 | Самая длинная общая последовательность | Julia | `2_task_4_julia` |

2.1 **Haskell.** Рекурсивное вычисление минимального числа операций (вставка, удаление, замена) для превращения одной короткой ДНК в другую.

2.2 **Scheme.** Задается рекурсивная функция, которая моделирует эволюцию популяции на протяжении N поколений. В каждом поколении рассчитываются частоты генотипов (p², 2pq, q²), после чего частота аллеля p слегка уменьшается на заданный коэффициент мутации. Рекурсия останавливается, когда проходит N поколений.

2.3 **Zig.** Поиск подстроки заданной длины K, которая встречается чаще всего в длинной РНК, используя скользящее окно.

2.4 **Julia.** Динамическое программирование. Итеративный поиск самой длинной общей последовательности для двух участков генома через заполнение двумерной матрицы.

## Тема 3. Ввод/вывод в консоль и файл

Папка: `3_io/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Парсер FASTA | Perl | `3_task_1_perl` |
| 2 | Инверсия цветов | Ruby | `3_task_2_ruby` |
| 3 | Статистика экспрессии генов | F# | `3_task_3_fsharp` |
| 4 | Подсчет стартовых кодонов | D | `3_task_4_d` |

3.1 **Perl.** Программа считывает файл формата FASTA, отбрасывает строки с заголовками (начинаются с `>`) и выводит чистую последовательность нуклеотидов.

3.2 **Ruby.** Чтение файла CSV, где записаны значения RGB. Программа инвертирует цвета и построчно пишет в новый файл.

3.3 **F#.** Расчет среднего арифметического и стандартного отклонения для набора чисел с плавающей точкой.

3.4 **D.** Чтение файла с последовательностью РНК и подсчет частоты появления кодона AUG.

## Тема 4. Клиент-серверное взаимодействие

Папка: `4_client_server/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Сервер транскрипции ДНК | Ada | `4_task_1_ada` |
| 2 | Математический сервер | Lua | `4_task_2_lua` |
| 3 | Детектор доминирующего цвета | Scala | `4_task_3_scala` |
| 4 | Справочник длин генов | Kotlin | `4_task_4_kotlin` |

4.1 **Ada.** Клиент отправляет строку ДНК. Сервер заменяет все символы `T` на `U` и возвращает готовую РНК клиенту.

4.2 **Lua.** Клиент передает серверу строку с базовым математическим выражением. Сервер парсит строку, вычисляет результат и возвращает ответ.

4.3 **Scala.** Сервер принимает пакет из трех чисел (R, G, B), определяет, какой цветовой канал имеет наибольшее значение, и возвращает его название.

4.4 **Kotlin.** На сервере в памяти жестко задан словарь (название гена -> длина). Клиент присылает название, а сервер отвечает числом.

## Тема 5. Конвертация данных из одного формата в другой

Папка: `5_convert/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | CSV в JSON | Groovy | `5_task_1_groovy` |
| 2 | ДНК в бинарный код | Swift | `5_task_2_swift` |
| 3 | HEX в RGB-кортеж | Objective-C | `5_task_3_objc` |
| 4 | Ключ-значение в XML-теги | Odin | `5_task_4_odin` |

5.1 **Groovy.** Ручная сборка валидной JSON-строки из формата CSV с использованием конкатенации строк.

5.2 **Swift.** Перевод текстовой строки ДНК в бинарный вид, где каждый нуклеотид кодируется 2 битами (A=00, C=01, G=10, T=11).

5.3 **Objective-C.** Перевод строки цвета из шестнадцатеричного формата (HTML) в формат `R: X, G: Y, B: Z`, конвертируя части строки в 10-тичную систему.

5.4 **Odin.** Парсинг простой записи вида `ключ=значение` и ручное оборачивание в XML-теги.
